# P2 双公司对比 AI 摘要 —— 设计与验收

> 上游：方案 C（对比先行）。P0 已交付确定性并排与差值，P1 已交付统一意图调度。
> 本文只解决一件事：**在"不让模型生产任何新事实"的前提下，让对比页产出一段有价值的摘要。**

## 一、要解决的问题

P0 的对比页是 9 行指标并排 + 差值。用户拿到的是事实，但要自己完成最后一步：把 9 行读成一段话，
并且知道"这段话覆盖不到哪里"。P2 补的就是这一步。

**验收问题**：用户打开对比页，原来做不到、现在能做到的那件事是什么？
→ 一句话得到"这几组已验证事实说明了什么、以及有哪些项因为数据缺失根本没进结论"。

## 二、核心口径（立项时拍板，不可放宽）

> **模型只能"组织"已验证的事实，不能"生产"任何新事实。**

这句话落到实现上是四道**确定性**闸门，模型不参与任何一道的判定：

| # | 闸门 | 位置 | 作用 |
|---|---|---|---|
| 1 | 事实包瘦身 | `toSummaryFacts` | 只把数值/单位/报告期/差值发给模型；证据 statement 原文、来源字段、计算口径**一律不进包**——模型没有可抄的自由文本 |
| 2 | 服务端重跑可比性 | `recheckFacts` | 客户端提交的行，服务端按 compare.ts 同口径重算一遍；声称的状态或差值与规则不符 → 整批 400 拒绝 |
| 3 | 数字锚定 | `validateCompareNarrative` | 每句必须声明 `metricIds`；句中每个数字必须能在**该句声明的指标**里锚定（含舍入变体）；锚不上 = 编造 → 整段拒收 |
| 4 | 判断词与合规 | 同上 | 优劣判断词（更好/更值得/领先/值得投资…）+ 既有合规禁语 |

**任何一道没过 → 不展示模型输出，降级为确定性摘要。**

### 2.1 为什么不让模型碰证据原文

P0 的证据 statement 是模型生成的自由文本，里面带着数字。如果把 statement 喂给摘要模型，
它就多了一条"看起来可信、其实不受控"的数字来源——这正是 P1-2 阶段踩过的 Evidence first 风险。
事实包里只有结构化字段，等于把模型的取材范围在物理上锁死。

### 2.2 数字锚定的放行边界

不是"所有数字都要锚定"（那会误杀"共 3 项指标"这类数量词），也不是"全放行"：

- **带单位的数字**（后面紧跟 `%` / `pct` / `个百分点` / `倍` / `x` / `元`…）→ 必须锚定；
- **无单位且 ≥10 的整数** → 必须锚定（防随口报数）；
- **无单位且 <10 的整数**（数量词）与 **1900–2100**（年份/报告期）→ 放行；
- 锚定容差 `0.051`：允许展示层舍入（`21.53` → `21.5`），不允许跨档（`21.5` ≠ `21.4`）。

## 三、降级链路（AI 失败不等于页面没内容）

`buildDeterministicSummary` 是**永远可用**的确定性摘要，不依赖模型：

- 可比项：念出两侧值 + 差值 + 报告期；
- 并列项：念出两侧值并声明"报告期不同，仅并列不计算差值"；
- 不可比项：只说"至少一侧无可用数据，不可比"，**不出现任何数字**；
- 末句：确定性生成的覆盖范围句（模型不参与计数，避免它自己数错）。

触发降级的三种情况：模型不可用 / 返回非法 JSON / 未通过闸门 3+4。
UI 上如实显示降级原因（琥珀色横幅），用户看到的仍然是真实数据，只是没有 AI 组织。

## 四、覆盖范围是产品信息，不是技术细节

模型**拿不到**不可比的行（连名字都不知道），只能看到"另有 N 项因数据缺失不在 FACTS 中"。
用户侧的"未纳入：市盈率、市净率"由服务端确定性生成并附在摘要末尾。

理由：让模型知道被剔除项的名字，它就有可能去推测这些项——而它们恰恰是没有数据的。

## 五、交互

- 显式按钮「生成对比摘要」，**不自动触发**（P0 的"零网络"承诺只对默认状态成立）；
- 页面头部文案同步改为"只有点生成摘要才会发一次请求"——不能一边发请求一边写"不发起网络请求"；
- 全部指标都不可比时按钮禁用，并说明原因；
- 每句摘要下方挂它引用的指标 chip（展示名，不暴露 metricId）；
- 失败横幅 + 免责说明常驻。

## 六、验收

单测 25 条（`tests/compare-summary.test.ts`，共 511 passed / 40 files），关键项：

- 事实包不含 statement / sourceFields（键集合断言）；
- 客户端声称可比但报告期不同 / 差值不符 / 并列带差值 → 全部拒绝；
- 不可比行不进事实包；
- 确定性摘要：可比带差值与报告期、并列声明不算差值、不可比不出现数字、末句为覆盖范围句；
- 闸门：编造数字、未知指标、未声明引用、判断词、合规禁语、超 5 句、空摘要 → 全部拦截；
 舍入允许；
- 放行边界：数量词与年份放行，`30` 这类无单位大整数拦截。

浏览器实测（真实模型 + 真实缓存数据）：见实现记录。

## 六之补充、实测结果与一处**已知局限**

真实浏览器 + 真实模型实测 **11/11 PASS**（种子数据写 IndexedDB → 点按钮 → 真实 LLM）：

- 摘要成功生成未降级；6 句（5 AI + 1 系统覆盖句）；句末覆盖率句准确（"7 项可比较、1 项并列、1 项未纳入"）；
- 句子回挂指标 chip；无优劣判断词命中；**无字段名泄漏**；
- 全部不可比时按钮禁用并说明原因；无未捕获 console 错误。

实测中发现并修掉的两个**文案问题**（都是我 prompt 设计的锅，不是模型乱来）：

1. 模型把字段名写进了正文——"差值AB为17.3pct"、"销售毛利率为side_by_side口径"。
   → 事实包字段改中文口径（`口径: "同报告期，可比较"` / `"报告期不同，仅并列"`），prompt 增加第 7 条
   **禁止任何字段名或英文标识进正文**，并给出中文表述范例。
2. 模型逐项罗列、不做归纳。→ prompt 明确"按组归纳（成长/盈利/现金流/估值），不要逐项罗列"。

### ⚠️ 已知局限：方向性陈述未做确定性校验

闸门 3 校验的是**数字能否锚定**与**指标引用是否存在**，没有校验"谁高于谁"这个方向。
模型理论上可能写出"A 比 B 高 17.3 个百分点"而实际是 A 低于 B——数字是真的，方向说反了。

为什么不修：要判方向就得解析自然语言的比较句式，脆弱且容易误杀，成本高于收益。
缓解：① prompt 明确要求按 A−B 陈述；② 差值列在同一行的正中间，用户一句对照即可发现；
③ 降级链路仍在——若模型触碰判断词或编数字，整段作废。

**这条局限必须写在交付文档里，不能当作已解决。**

## 七、边界（不做）

- 不做"哪家更好""更值得投资"——判断词在闸门里被拦，不是靠 prompt 自觉；
- 不做跨公司研究库筛选（P3）；
- 摘要不写回 payload、不进研究空间，是一次性组织结果，刷新即消失。
