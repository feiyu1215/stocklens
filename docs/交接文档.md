## 一、这是什么项目

**A 股个股证据研究工具**：选一家公司 → AI 围绕它生成研究维度 → 确定性代码计算全部金融数字 → 每条结论可回溯到原始证据，无证据返回 UNKNOWN。不评分、不预测涨跌、不给买卖建议。

**产品原则（一切迭代的底线）**：Evidence first. Conclusions second.

**项目性质**：求职作品。交付物 = 可访问的 Web URL + 提交包 + 文档，所以"演示故事讲得顺不通顺"和"功能存在"同等重要。

## 五、环境与运维（每个坑都真实踩过）

**部署**
- `npx vercel --prod --yes --token=<用户提供的token>`。**没有全局 vercel**，别用裸 `vercel`。
- **GitHub 没有 Vercel Git 集成**（`gh api repos/.../commits/<sha>/status` 返回 `total_count: 0`），push 不会触发部署——部署必须手动。
- token 会丢/会过期（auth.json 曾整目录消失，`.env.local` 里的 VERCEL_OIDC_TOKEN 是 development scope 且已过期）。丢了就让用户去 Vercel 后台重签，**不要把 token 写进任何文件**。

**网络**
- `api.vercel.com` 可直连（部署不需要代理）；`*.vercel.app` 页面检查**必须走代理** `http://127.0.0.1:7890`。
- 代理经常挂：`curl` 报 `fetch failed` / `exit 7` = 代理死了，先 `curl -x http://127.0.0.1:7890 ... -w "%{http_code}"` 测代理再重试，别急着怀疑代码。

**本地开发/测试**
- dev server 常驻 3100；**必须用 `localhost`**，用 127.0.0.1 会 cross-origin 弄坏 HMR（页面停在 SSR 加载屏）。
- 本地 `next build` 会跑到 9 分钟+不结束；**别拿它当部署门槛**，以 Vercel 云端构建为准（同一代码 15s）。
- playwright：模块在 `C:\Users\57709\.workbuddy\binaries\node\workspace\node_modules`（`NODE_PATH` 引入，脚本用 `.cjs` 因为 ESM 不认 NODE_PATH）；浏览器 executablePath 指 `C:\Users\57709\AppData\Local\ms-playwright\chromium-1234\chrome-win64\chrome.exe`。
- **探针两大坑（会得假 PASS/假 FAIL）**：① 画布 init 期间的加载屏自己也带"← 返回研究库"链接，不等到 init 结束（轮询到"中止等待"消失）就采样会测错对象；② 手机端首次访问首页会被重定向到画布（`localStorage["stocklens.entry.mobile.v1"]`），模拟回访用户必须先写这个标记，否则"到了首页又被弹回"会被误判成"点了没反应"。
- 种子数据：IndexedDB `stocklens` 库 `kv` store，记录 `{key, value}`，key 形如 `stocklens.research.000333.SZ`，value 是 `{ payload, recordedSample }`。自己 `indexedDB.open("stocklens")` 时要处理 `onupgradeneeded` 建 store。

**提交纪律**
- 每轮改完：`npx tsc --noEmit` + `npx eslint src tests` + `npx vitest run` 全绿 → 主题化提交 → `npm run package:submission` 重打提交包（**必须在最后一次代码修改之后**，否则交付源码缺修复）→ 部署 → **生产实测**。

## 六、产品纪律（改任何东西之前先读这节）

1. **Evidence first**：金融数字只来自结构化 metrics（确定性引擎），AI 文本一律不得成为数字来源。P2 摘要的"事实包不含证据原文"就是这条的落地——**别为了省事把 statement 喂给任何模型**。
2. **合规是确定性防线，不是 prompt 自觉**：新通路必须接 `detectRestrictedInvestmentRequest`（请求预检）+ `findForbiddenOutputPhrases`（输出禁语），并且**上生产用真实问法复验**（P1 就是在生产上发现"推荐明天涨幅最大的股票"漏接的）。
3. **缺失数据不伪造零值**：三级可比性（comparable / side_by_side / not_comparable）是确定性规则，AI 不参与；不可比绝不推导。
4. **示例/真实数据必须可辨**：录制示例有琥珀色徽标，混合对比要明示。
5. **server-only 纪律**：client 组件严禁把 server-only 模块链进 bundle（Next 会直接报错，阶段 4 踩过）；client-safe 纯函数与 server 实现分文件放。
6. **`data-*` 属性是验收接口**：探针脚本全靠它们定位，改属性名前先 grep `.tmp/`。
7. **失败要诚实可见**：AI 失败/降级要有明确的 UI 状态和原因，不静默、不假装成功。
8. **只展示可验证的部分**：缺失侧渲染"—"和横幅，不渲染编造的行。

## 八、与用户协作须知

- **文档类改动先确认**：项目里"按建议修复"默认指改代码/产品；本次交接文档是用户明确要求的例外。
- **破坏性操作先给非破坏备选**（卸载、删目录类），等用户拍板。
