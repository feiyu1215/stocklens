# Known Limitations

本文件只列**当前真实存在**的限制。产品对每一项都有明确行为——要么绕开，要么如实呈现，不会假装它不存在。

> Task 17.1 已修复并从本文件移除：Reading 头部路径行与标题重叠、首次访问提示卡写「观看 60 秒演示」、取消等待的确认文案不可见、以及"数据过期缺少机制性防护"。当前的新鲜度行为见 README 与 `架构说明.md`。

---

## 1. 研究初始化需要约 15–30 秒

**事实**：首次进入一家公司时，Research Framer 与 Composer 两次真实模型调用占掉 94–97% 的时间（数据层取数 + 指标 + 证据仅 0.17–0.6 秒）。

**产品怎么做**：用**全屏研究过渡**承载这段等待——大字号目标公司身份、真实已等待秒数、五个中性占位（只表达"研究角度尚未解析"，不预写任何金融语义）、以及随时可用的「← 返回上一家公司」。取消后画布上会短暂显示「已取消等待」，明确这次等待是被用户中止、而不是失败。**不做**假进度条、百分比或剩余时间预测：在没有可靠预测的前提下，那些数字就是编造。

**为什么不做流式/并行优化**：先测再优化。当前瓶颈已被定位到模型串行调用，而不是取数；在没有明确要求前不引入流式架构。

## 2. 移动端采用阅读路径

**事实**：这是一个以 1440×900 为设计基准的研究画布。

**产品怎么做**：在 1280×800 与 1440×900 下保留完整空间交互。小于 768 px 时使用独立的研究维度列表，点入后以全屏 Reading / Evidence 阅读，并可返回列表；390×844 已在 Chromium 应用内浏览器实测。移动端不提供维度拖拽、相机缩放和平移，这些空间操作仍限定在桌面画布。

## 3. Follow-up 是原子 JSON，不是流式

**事实**：`POST /api/followup` 一次返回完整结果。

**产品怎么做**：界面上的 `Reviewing current evidence…` 是**进度态**，不假装 token 流；`■ Stop` 只取消浏览器侧请求，文案只说「Stopped by you」，**不声称服务端计算已取消**（后端没有取消端点）。失败时只在线程内提示并提供 `Retry answer`，不影响画布与证据。

## 4. 模型看不到对话历史

**事实**：每一轮追问只携带当前 scope（公司/维度/claim/证据）与相关证据 ID；后端**不接收**历史轮次。

**产品怎么做**：线程历史完整保留在客户端供用户回看，scope 变化时插入 `CONTEXT CHANGED → …` 分隔线而**不清空历史**；界面不暗示模型记得上一轮。这是诚实的做法——多轮上下文能力当前不具备，就不呈现成具备。

## 5. 不支持的能力一律返回 UNKNOWN

**事实**：扶摇当前不提供新闻/公告类接口；历史估值序列与部分行业字段未接入。

**产品怎么做**：对应维度直接落为 `unknown`，并列出**缺什么**（例如「同行财务位置暂无法验证」「未接入历史估值序列」）。`UNKNOWN` 是正式结果，带 `unavailableReason`，在 UI 上以独立分区呈现，文案明确说明"这不是负面证据，也不是系统错误"。**绝不**用模型补一段听起来合理的解释。

## 6. 同行比较是行业级，不是成分股级

**事实**：已实现的是**行业级**比较——个股 PE/PB 与行业成分股中位数之差（带有效样本数，过滤 PE≤0），以及个股相对行业指数的区间表现。

**未做**：逐家成分股的财务报表级对标（营收/利润/现金流横向排名等）。产品对此的态度是显式声明未接入，而不是用行业均值冒充逐家对比。

## 7. 时间敏感数据的新鲜度阈值是固定的 7 个自然日

**事实**：行情、估值快照、行业指数行情与事件核查按数据日期与 **7 个自然日**阈值判定 `fresh` / `stale`（财务报告期数据不参与该判定）。这个阈值是保守的固定值，覆盖周末与短假期，但不区分不同市场的休市安排（例如长假）。

**产品怎么做**：超过阈值即标 `stale`，并在结论里显式声明"当前状态无法由该数据确认"；无法取得数据日期时标 `unknown`，绝不默认按新鲜处理。阈值本身可作为后续可配置项。

## 8. 画布快照只在同一标签页会话内恢复

**事实**：会话内的研究结果最多缓存 30 分钟，期间切回公司可直接恢复。整页 reload 会从 `sessionStorage` 恢复相机、维度位置、停放项、选择与便签；恢复前会按新载荷中的维度 ID 做协调，已不存在的维度引用会被过滤。研究数据本身仍会重新初始化，超过 30 分钟的公司缓存也会重新取证。

**产品怎么做**：恢复只覆盖同一浏览器标签页会话；新标签页、其他设备与账号之间不做同步。维度集合发生变化时只恢复仍能映射的部分，避免把旧位置错配给新维度。

## 9. 明确不在产品范围内

没有用户系统与账号；不跨标签页、设备或账号持久化诊断历史；不做 K 线图与图表库；不接入新闻/公告；不做语音；不做多公司并列对比视图；不提供投资组合、自选股推荐或任何形式的收益预期。

## 10. 关于"没有做到的"与"有意不做的"

- **没有做到**：第 7 条仍是明确缺口；第 8 条已支持同一标签页刷新恢复，但跨标签页、设备和账号同步仍不在范围内。
- **有意不做**：流式输出、假进度、评分/评级、买卖建议、涨跌预测、用 LLM 计算数字、在数据缺失时生成"正常"结论——这些是产品纪律，不是遗漏。
