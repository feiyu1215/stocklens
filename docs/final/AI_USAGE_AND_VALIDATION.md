# AI Usage & Validation

本文件说明**搭建 StockLens 时使用了哪些 AI 工具**、**产品内部哪些环节使用 AI**，以及**候选人（人）在哪些地方否决、纠正或重做了 AI 的输出**。

区分两件事：

- **AI used to build StockLens** —— 用来写代码、做审计、查资料的工具；
- **AI used inside StockLens** —— 产品运行时真正调用的模型与它被允许做的事。

---

## 1. AI Tools Used

**用于构建产品：**

| 工具 | 用途 |
|---|---|
| ZCode（编码 Agent，基于大模型） | 按逐轮下发的 Task prompt 实现功能、跑测试、做浏览器验收、写审计文档。全程由人下发规格、审阅产出、否决方向 |
| 浏览器自动化 + DOM 断言 | 由 Agent 驱动的真实指针/键盘验收（不是人肉点，也不是只看截图） |

**用于产品运行时：**

| 组件 | 模型 / 方式 | 只允许做什么 |
|---|---|---|
| Research Framer | DeepSeek（temperature 0） | 依据公司身份、行业与用户问题，**命名** 4–6 个研究维度并给出理由 |
| Composer | DeepSeek（temperature 0.2） | 把某维度下**已存在**的证据组织成 claims |
| Follow-up | DeepSeek（temperature 0.2） | 围绕当前 scope 的证据做有依据的追问回答 |

模型看不到原始财务数字（只收到白名单化、已构造好的 Evidence），不能调用数据源、不能重算数字。

## 2. Where AI Participated

**产品实现**：几乎全部代码由编码 Agent 按规格实现——数据适配、指标引擎、证据引擎、API 路由、研究画布与子界面、测试、打包脚本。

**产品运行时（三个受约束的环节）**：Research Framer、Composer、Follow-up。三者的输出都经过确定性校验（证据绑定、分区类型、合规扫描），失败一次会修复重试，仍失败则该维度 `synthesis = null`，**证据照常返回**。

**工程辅助**：测试用例编写、缺陷复现脚本、审计文档初稿。

**AI 没有参与的环节**：所有金融计算（同比、单季还原、区间收益、波动率、最大回撤、估值比较、行业相对表现）、证据的构造与分类、冲突规则触发、合规判定、UI 交互逻辑。这些全部是确定性代码，并由单测锁定。

## 3. Human Validation and Corrections

以下每一条都是**候选人否决或纠正 AI 输出的真实记录**——这些是本项目最重要的验证证据。

### 3.1 热榜排名 323 → 334 不得写成"关注度提升"

数据事实是排名从 323 名变为 334 名（**退后**）。AI 的初版表述把它写成了"关注度提升/热度上升"。候选人否决：排名类数据 rank 越小越靠前，**不得改写原始 statement 的措辞**，更不能把数值变化叙述成相反的方向。修正后该记录只做原文转述。

### 3.2 低基数与符号翻转：不能让异常增长率读起来像"正常增长"

某期经营现金流同比 −1600.72%，原因是上年同期基数极低（绝对值仅 2.48 亿）而非经营崩塌。AI 的初版解读写成"现金流极端恶化"。候选人要求引入**确定性护栏**：低基数（上年同期 < 自身历史单季中位数 ×10% 且样本 ≥4）、符号翻转、极端变化（≥500%）三类标记，并在文案中强制解释成因；护栏**绝不修改数值**，只改变解读守卫。修正后该期正确标注为"基数效应导致的高波动"。

### 3.3 Evidence Context Budget：不是所有证据都该塞给模型

早期实现把公司全部证据一次性送给合成模型。候选人指出这既浪费 token 又稀释重点，要求引入**确定性打包策略**（冲突 > 推断 > 未知 > 负面 > 正面 + 主维度最低 1 条 + 单维度上限）。实测同一问题的输入从 8391 字符降到 3537 字符（−57.8%），首屏结论质量反而更稳定。

### 3.4 动态维度的落地：不支持的维度必须变成 UNKNOWN，而不是编造证据

当用户添加一个当前数据不支持的研究角度（如"库存压力"——扶摇没有库存字段）时，AI 倾向于生成一段听起来合理的解释。候选人要求：**必须**返回 `status = unknown` 的维度、列出缺失的数据项、并在 UI 上标注证据不完整。实测「库存与周转压力」正确落为 UNKNOWN + `Evidence incomplete`，没有编造任何数字。

### 3.5 Research Framer：公司类型与问题必须影响维度，固定枚举被否决

AI 的初版实现把诊断维度写成固定枚举（一套模板套所有公司）。候选人否决：必须由模型依据**公司类型 + 用户问题 + 真实能力清单**自由命名维度，并在 prompt 中明令禁止"对每家公司套用同一组标签"。修正后可观察到的差异：制造业得到"盈利质量 / 现金转化 / 估值相对位置"，银行得到"盈利质量与资本回报 / 资产质量与风险抵补 / 估值安全边际与行业相对"。

### 3.6 重复 `research/init`：浏览器审计发现，候选人修正编排

浏览器审计中观察到**一次公司选择触发了两次 `POST /api/research/init`**。候选人没有接受"看起来能用"，而是要求先枚举全部 init 调用点、再定位到"同一次选择把切换函数调了两次"，最后按 stockCode 做**在途去重**（并保留"刷新研究"作为显式绕过去重的路径）。修复后在多轮真实指针验收中复验为恰好 1 次。

### 3.7 视觉交互失败：按钮"存在"不等于"点得到"

多轮浏览器验收曾以"元素在 DOM 中且 `isVisible()` 为真"判定通过。候选人否决这种判定标准：**必须用真实指针**（浏览器产生的可信输入事件，不是 `dispatchEvent` 合成事件）。改用真实指针后立刻暴露了 7 个同族缺陷，其中包括：全屏过渡层的「返回上一家公司」按钮被同级内容层完全覆盖（在按钮矩形内取 50 个采样点，**0 个**命中按钮）；演示结束帧的 CTA 位于 `pointer-events-none` 层内；首次访问提示卡盖住公司切换器的最近列表 92% 宽度。这些都不是"打磨问题"，而是"用户根本点不到"。

### 3.8 Guided Demo：AI 写的调度器卡死在第一幕

AI 生成的演示实现会在第 1 个场景后永久停住。候选人定位到根因不在动画，而在 **effect/timer 生命周期**：场景调度 effect 的依赖随无关状态变化而反复重建，cleanup 把本场景的定时器全部清掉。修正是把排程函数放进 ref，effect 只依赖真正决定排程的键（场景号 / 暂停标志）。修复后六幕按 5/6/7/12/8/12 秒的编排完整推进。

### 3.9 公司切换 15–30 秒：候选人选择"如实表达等待"而不是假进度

性能审计显示数据层只占 0.17–0.6 秒，**94–97% 的时间是两次模型调用**。AI 的初版做法是在角落放一个小 loading 卡片（读起来像卡死）。候选人否决，并要求把等待本身做成页面：全屏研究过渡、真实已等待秒数、明确可返回上一家公司，**禁止百分比与剩余时间预测**（没有可靠预测时任何进度数字都是编造）。同时明确本轮**不做**流式/并行优化——先把真实的等待讲清楚。

### 3.10 其它被否决的 AI 输出（简述）

- **模型伪造证据 ID**：合成结果出现过引用不存在的 `EV_*`，被确定性校验拦截（整体拒绝 + 一次修复重试，而不是悄悄删掉引用）。
- **能力组 UNKNOWN 的误判**：早期实现把"本轮未执行该维度"与"执行了但数据不可用"混为一谈，候选人要求加"该域指标至少存在一个"的守卫。
- **无证据归因**：模型曾试图用"资金出逃/预期下调"解释价格变化，被规则拒绝；正确回答是"当前证据不能完整归因"。
- **表格化"本次结论"**：AI 生成的评分/评级字段被候选人整体移除——证据引擎的契约里明确禁止 signal 之外的 score/rating 字段。

## 4. How AI output is validated in the product

不是"相信模型"，而是三层确定性拦截：

1. **证据绑定校验**：claims 里引用的每个 Evidence ID 必须真实存在；伪造即整体失败，不静默删除。
2. **分区类型校验**：FACT / INFERENCE / UNKNOWN 的字段与置信度组合有强制不变量（例如 unknown 必须 `confidence=low`、`verifyStatus=unverified`、带 `unavailableReason`）。
3. **合规扫描**：确定性预检 + 输出扫描，拦截涨跌预测、收益承诺、买卖建议类表述。

任一失败 → 修复重试一次 → 仍失败则该维度 `synthesis = null`：**证据仍然完整返回，AI 的失败不会污染事实层，也不会被伪装成正常结论**。
