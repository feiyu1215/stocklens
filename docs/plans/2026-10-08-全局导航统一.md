# 全局导航统一 —— 问题、审计与结果

> 起因：用户提了一个交互点——"进入研究矩阵那一页想返回首页，除了上滑，也应该和研究空间的逻辑一样，点左上角那个东西也 OK；把通用的交互按钮让它全局都起作用"。

## 一、先审计，别凭代码猜

写了只读探针（`.tmp/nav-audit.cjs`）逐面跑：每个页面左上角**是什么元素、可不可见**，再单独验**点了去哪**。桌面 1280 与手机 390 两档。

审计结果（修改前）：

| 页面 | 左上回首页 | 研究库入口 |
|---|---|---|
| `/` 首页 | ✅ 可点 | ✅ |
| `/research` 研究矩阵 | ✅ 可点（点了确实回 `/`） | ✅ |
| `/research/compare` 对比页 | ❌ **完全没有** | ← 研究库 |
| `/lab/...` 研究空间（桌面） | ✅ | ✅ |
| `/lab/...` 研究空间（手机） | ✅（被移动端页面盖住） | ❌ 整组右上导航被藏 |
| 手机端研究页顶栏（`MobileResearchList`） | ❌ **`STOCKLENS` 是纯文字，不是链接** | ← 研究库 |

三点结论：
1. 用户说的"研究矩阵页左上角点了没反应"——**研究矩阵（`/research`）本身是好的**，真正点不动的是**手机上盖在画布之上的那个移动端研究页**，它的 `STOCKLENS` 写成了 `<span>`；
2. 对比页**一个回首页的出口都没有**；
3. 手机上画布顶栏把整组右上导航藏了（放不下），研究库入口跟着消失。

**教训**：这类"某个按钮怎么这儿没有"的问题，靠读代码会得出"不是已经有吗"的错误结论——三个面各写一份导航，漏一个从代码上完全看不出来，必须逐面实测。

## 二、做法：一个组件，两种模式

新建 `src/components/v5/GlobalNav.tsx`——品牌标（回首页）+ ▦ 研究库，`data-home-nav` / `data-library-nav` 契约统一。

- `mode="link"`：独立页面走路由跳转（对比页、移动端研究页）；
- `mode="action"`：首页/研究库是同一组件的两个面，切换**不换路由**，交给上层回调（保持原行为：`surface` 切换 + 下划线指示）。

接上的位置：首页/研究库（action）、对比页（新增，此前没有）、移动端研究页（把死文字换成链接）、画布顶栏（保留它更丰富的右侧集群，另给手机补一个紧凑的研究库出口）。

## 三、验收（真实指针，非"handler 存在"）

| 检查 | 结果 |
|---|---|
| 5 个面 × 桌面/手机，两个出口均可见 | ✅ 10/10 |
| 对比页点品牌标 → `/`；点 ▦ → `/research` | ✅ |
| 研究矩阵点品牌标 → `/` | ✅ |
| 研究空间（录制示例）点品牌标 → `/` | ✅ |
| 首页点 ▦ → 切到研究矩阵面（不跳路由）；再点品牌标 → 切回起始面 | ✅ |
| 移动端研究页：品牌标是 `<a href="/">`、顶栏不溢出、不与示例徽标重叠、点了落到 `/` | ✅ 6/6 |
| 研究空间顶栏（等 init 完成后再判）两个出口可见 | ✅ 4/4 |
| P2 对比摘要回归 | ✅ 11/11 |
| 单元测试 | ✅ 512 passed / 40 files |

**两个测试自身的坑（值得记住）**：
1. 画布初始化期间显示的是加载屏（"← 返回研究库 / 中止等待"），它**也带研究库链接**——不等到 init 结束就采样，会把加载屏的元素当成顶栏，得到假 PASS；
2. 手机上从画布点回首页，**首页会被既有的"移动端首次访问重定向"弹回画布**——不先写 `stocklens.entry.mobile.v1` 标记模拟回访用户，就会把"其实到了首页又被弹回"误判成"点了没反应"。

## 四、仍未统一的一处（如实记录）

画布顶栏在 `workspaceLab && aiOpen && readingId`（Lab 工作区 + AI 面板打开 + 正在读一个维度）时**整条 header 不渲染**，此时没有任何全局出口，只能按 Esc 退出。这是当初为了把画面让给阅读内容的有意设计，本次未动——要改需要先定"全屏阅读时全局出口放哪"，属于设计决策而不是修 bug。
