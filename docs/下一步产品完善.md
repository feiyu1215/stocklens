# 下一步怎么完善 · v2（2026-10-10 凌晨）

> v1 是 2026-10-09 深夜版。v2 吸收了一轮交叉评审，**修订的都不是措辞，是实质**：
> ①变化不能拿 statement diff 充当；②快照不能每次进入机械保存；③判断层的"可追溯"不等于"判定标准合理"。
> 另补两条读代码才知道的事实 + 一个新字段缺口 + 模块改名（避免与既有 P1 撞名）。
>
> 一句话结论不变：**复杂的不是"再多做几个功能"，而是三处结构性张力**；
> 完善方向是把已存在的能力兑现成用户能感知的价值。变化顺序有了，收紧程度也有了。

## 一、变化的四类语义（v2 采用）

| 类型 | 判据（结构化） | 产品表达 |
|---|---|---|
| **数值变化** | 同 metricId + 同 period，`value` 差值越过阈值 | 展示前后值与差额，标注口径一致 |
| **报告期变化** | 同 metricId，`period` 由 A 变 B | 明确标注报告期切换；**切换期的指标默认按"不可比"处理**，不直接算差额 |
| **证据变化** | 核心指标未变，但 evidence 的 statement / sourceFields / freshness 变了 | 只标"证据已更新"，**不夸大成经营变化** |
| **结论状态变化** | claim 依赖的 evidenceId 命中上述三类 | 标"需重新核验"，**不宣布结论反转** |

### 明确"不算变化"的清单（防止噪音）

- 舍入级波动未过阈值（`MetricResult.value` 是**未舍入原值**）
- 报告期不同导致**口径不可比**（如 2025-Q4 的年度值 vs 2026-Q2 的半年度值）
- `unavailable → available` 且没有同期对照（属于"补齐"不是"变化"，单独走缺失提醒）
- 首次进入、无基线快照（出"已建立首次研究记录"，不报变化）
- **录制示例模式**（真实数据不得并入示例）

### 一个代码层实情（v2 新增，读代码才知道）

**`ResearchSpacePayload` 目前没有顶层 `retrievedAt`**（核实 `src/components/observatory/theme.ts:37-52`：字段只有 spaceId / company / frame / dimensions / claims / evidence / suggestions / trend / metrics / marketHistory / ai / errors）。
要区分「新报告期入库」与「数据方修正同一报告期」，payload 需要一个取数时间戳。方案：
**additive 增加顶层 `retrievedAt?`**（刷新端点 `RefreshResponseLike` 已在返回该字段，`mergeRefreshedTruth` 顺势写入即可，不破坏老 fixture）。
分类判据因此完整：

- period 变 → 报告期变化
- period 不变 + value 变 + retrievedAt 变 → **数值变化（数据源修正）**
- period 与 value 都不变 + evidence 变 → 证据变化

### 一个可行点（v2 新增，v1 没用上）

纵向口径校验可**复用对比页已有的可比性闸门**：`src/lib/v5/compare.ts` 的 `CompareStatus = comparable | side_by_side | not_comparable` 与 `buildCompareRows`。
"同公司跨期"和"两家横向"是同一个口径问题，不必写第二套规则。

### 阈值（2026-10-10 已收紧，见下方"阈值复核"）

**阈值复核（2026-10-10）**——原草案有两个真问题，已改：
1. **% 类不再一刀切**：`unit="%"` 同时覆盖 growth 组（营收/净利润/现金流同比，波动大）与 profitability 组（毛利率/净利率/ROE，水平值）。统一 0.5pct 对增速太敏感 → 改为 **增速 1.0pct / 水平比率 0.5pct**。
2. **相对变化率加"基数护栏"**：倍数类（经营现金流/净利润）与估值类在分母趋零（微利）时相对变化率会爆炸（0.01→0.05 即 +400%），这是算术假象不是经营变化 → `|基准| < 0.05` 时**改报绝对差并标"需核验"**，不静默丢弃（那会漏掉真实修正）。

| 指标量纲 | 建议粒度 | 理由 |
|---|---|---|
| 比率类（毛利率 / ROE / 同比%） | ≥ **0.5 个百分点** | 小于此多为舍入与口径噪声 |
| 金额类（营收 / 现金流） | ≥ **5%** | 绝对值跨公司不可比，须相对差分 |
| 估值类（PE / PB） | ≥ **10%** 且价格或 EPS 有变动 | 估值派生自价格，避免被动波动误报 |
| 带 `interpretationFlags`（low_base / sign_flip_base / extreme_change）的指标 | **永不当普通数值变化报**，降级为"需核验" | 现有护栏必须尊重 |

## 二、历史快照规则（v2 收紧）

```
加载存档 + 拉取更新候选
  → 保留旧数据，不立即覆盖
  → 服务端返回 → 结构化 diff（typed）
  → 是否值得记录？
      否 → 只更新 lastCheckedAt，不新增快照
      是 → 先写 prev 快照 → 再提交新 payload（失败即回滚，旧数据不动）
  → 展示变化清单
```

- **M1 只保留「上一个有效版本」+「本次变化清单」**；多版本时间线留到 M3（P1）。
- 快照内容：`{ savedAt, retrievedAt, metrics, evidence, claims 摘要 }` —— **metrics / evidence 存全文对象**，不是只存 id。
- **示例模式不参与**：录制示例已跳过自动更新（2026-10-09 已落地），天然不会让真实数据混入示例；但该边界要在**研究库 / 对比页 / 证据详情**三处都能被识别（M2 检查项）。

## 三、判断层（v2 收敛）

| 层级 | 定义 | 处理 |
|---|---|---|
| 事实 | 毛利率 25% → 23% | 已有，直接展示 |
| **条件性判断** | 按预设阈值与适用边界触发信号 | **M4（P2）先做这一层** |
| 综合评价 | "盈利质量差""估值昂贵" | 暂不自动生成 |

起步信号不选"估值偏贵"（需要行业 / 盈利阶段基准，判定标准难立），改选**同报告期内的关系型信号**：收入增长与利润增长背离、现金流与利润匹配度。它们只需要"同一报告期的两个数字 + 一个阈值 + 一条适用边界"，最容易立住"可验证"。

## 五、M1（P0）五项验收（照评审边界，落地为可测项）

1. **幂等**：连续多次进入同一家公司且数据无变化时，不产生重复快照；更新失败时旧 payload 完好。
2. **分类正确**：能从结构化字段识别并区分 数值 / 报告期 / 证据 / 结论状态 四类。
3. **不误报**：舍入级波动、跨期不可比、缺失转有值均不被报为"经营变化"。
4. **可定位**：每条变化能打开依据，并正确定位 公司 / 指标 / 报告期 / 证据卡。
5. **不破坏**：自动更新失败时保留原数据，研究空间与对比功能不受影响。

补充一条内部红线：**自动更新目前每次都在写 payload（即使无变化）** —— M1 必须把它改成"有值得记录的变化才落盘"，否则本机存储会被无意义写入刷爆。

**落地时推翻了自己原先的设计（两点，都写在这里以免以后又走回去）：**

1. **删掉了"收入与利润增长背离"这条规则**。原计划（含交叉评审）点名要它，但核到 `rules.ts:114` 时发现证据层早就有 `RULE_FIN_PROFIT_GROWTH_LAGS_REVENUE`（阈值 1.0pct）+ `RULE_FIN_REVENUE_PROFIT_DIVERGENCE`（收入增、利润降），两者合起来已覆盖我这条的全部触发情形；我设的 10pct 只是它的子集——同时触发等于同一件事说两遍。判断层不重复证据层，故删除。
2. **两条规则在两个录制样例上都不触发**（美的 CFO/净利 1.42；茅台 1.59 且累计/单季异号）。没有靠调低阈值去"制造"触发——那是为了演示好看而扭曲判定标准。改法是让**沉默本身可核验**：面板列出每条规则的阈值与实际数字，"未触发：经营现金流 / 净利润 = 1.42 倍，未低于阈值 0.8"。

**顺带修掉两个真缺陷（都是探针抓出来的，不是预想的）：**
- 未被任何维度卡引用的 FACT 证据（如 `EV_FACT_FIN_REVENUE_YOY_YTD`）在 M1 变化面板和 M4 判断层里都渲染成可点按钮，点了什么都不发生。改为：可定位才渲染按钮，否则标"未挂维度卡"，不假装能跳转。
