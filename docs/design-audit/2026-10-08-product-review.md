# StockLens 产品级审视（2026-10-08 · 重档）

范围：本地版本（`/`、`/research`、`/lab/ai-workspace-v1`、`/observatory-v5`）。
方法：以仓库一手文档（README / SUBMISSION / 已知边界 / 测试说明 / 本审计前两轮实测）为事实底，推断处单独标注。
前置结论：本轮三项工作（研究库往返修复、自动排列恢复参差有序、RouteWipe 全路由过渡）已落地并实测通过，不再重复展开。

---

## 第一重 · 问题与领域

**产品是什么**：个股证据诊断工具——把一家 A 股公司的当前状态组织成可探索的研究画布，AI 生成维度、确定性代码负责全部金融数字、每条结论可回溯到证据，无证据返回 UNKNOWN。

**现在真正的问题不是"该加什么功能"，而是"产品的哪一层还薄"**。核心研究闭环（维度 → 证据 → 追问 → 溯源）已经完整且罕见；此时堆功能的收益递减，结构性的断点才是主要矛盾。

**判断主轴候选**：
1. 证据密度（每屏可验证的信息量）
2. 研究过程的完整与连续（进去 → 深入 → 回来 → 再来）
3. 可信度的呈现（诚实纪律是否在每一层可见）

---

## 第二重 · 理论体系与判断主轴

| 框架 | 在 StockLens 上的判读 |
| --- | --- |
| **Norman：概念模型与可视性** | 产品的概念模型是"组织一个研究过程"。这个模型必须在评审者进入后的十几秒内可见。裸画布（无首页叙事、无研究库）让概念模型只剩画布本身——过程感丢失。 |
| **信息觅食（Pirolli & Card）** | 向前的"信息气味"（锚点→证据→钻取）已经做得很好；缺的是**向后的气味**：钻到证据深处后能否低成本回到研究脉络？离开后能否找回上一次研究？即**研究连续性**。 |
| **芒格逆向** | 反过来问：什么会让评审在 60 秒内失去信任？①等待无解释（已解决：中止/重试/文案升级）；②搜索空结果无任何反馈（已知边界自认）；③看到的版本与文档描述不一致（见第三重事实 1）。 |
| **JTBD** | 用户"雇佣"它完成的任务是：**为一家陌生公司建立一个有据可查的判断起点**——不是荐股、不是行情终端。一切迭代按这个任务打分。 |

**定版判断主轴 = 2 + 3 的合取**：研究连续性 × 可信度呈现。1（证据密度）已达标，不再作为主攻方向。

## 第三重 · 关键事实与综合

### 事实 1：入口碎片化是当前最大的结构性问题（一手证据）

| 事实 | 出处 |
| --- | --- |
| README 顶部、Live Demo、Run Locally、国内直连地址**全部指向 `/observatory-v5`** | `README.md:9/12/20/25-26/112` |
| `/`（首页）与 `/research`（研究库）是新增路由，**尚未提交、更未部署** | `git status`：`src/app/page.tsx` 修改，相关 v5 组件改动未跟踪 |
| `/observatory-v5` 与 `/lab/ai-workspace-v1` 是**两个不同的画布实例**：后者才有 AI Sidekick、本轮的失败态重试/中止、RouteWipe 出口 | 组件结构 + 本审计第二轮改动清单 |
| ⇒ **线上评审者与外部用户看到的，是一个没有首页、没有研究库、没有 Sidekick、没有本轮任何修复的版本** | 推断（由上三条直接推出） |

这意味着本地两个月的迭代（叙事层、动效语言、诚实兜底）在交付口径里**整体不可见**。这不是"要不要优化"的问题，是"评审看到的和产品是不是同一个东西"的问题。

### 事实 2：等待体验已经闭环，但还有两个可信度缺口

- 15–30 秒 init：94–97% 是两次真实模型调用，**数据层只占 0.17–0.6 秒**（README Known Boundaries）——这个数字是后面"证据快刷"可行性的直接依据。
- 已落地：全屏真实等待 + 可中止 + 失败重试 + 30s/90s 文案升级（本审计第二轮）。
- **缺口 A**：搜索港股/美股返回空列表且**界面无"无结果"提示**（已知边界.md 自认，"交付冻结期间未新增"）。
- **缺口 B**：README Validation 写的是"409 个测试 / 30 个文件"，实际已是 **417 / 32**——文档与事实漂移，对一个以"可验证"为卖点的产品是自伤。

### 事实 3：研究连续性目前只到"同标签页刷新"

- README：无用户系统、不跨标签页/设备同步；**同一标签页刷新**才恢复兼容的画布快照。
- 研究库表格已有「最近研究」列（`ResearchHome.tsx` COPY.columns），但按 README 口径这个状态不跨会话——研究库目前是静态目录，不是研究资产。
- 推断：浏览器的 localStorage/IndexedDB 完全够存"我研究过哪些公司 + 各自的 payload 快照"，不需要用户系统就能把研究库变活。

### 事实 4：视觉与动效语言已基本统一

- `PALETTE` 单一色板（amber 规范漂移已修）、favicon 复刻光圈母题、RouteWipe 统一跨路由动效、`tabular-nums` 画布内已使用（`CanvasAnchorLayer` / `ResearchCanvas`）。
- 剩余的 UI 断点只有一处结构性差异：**首页/研究库是编辑排版（editorial），画布是空间化界面**——两者密度差异大，靠 palette 统一颜色，但版面气质的衔接只有 RouteWipe 一层。这是可接受的过渡，不是必须修的缺陷。

## 第四重 · 反方压力

**反"先做入口收敛"**：如果交付仍处冻结期，改 README/部署口径会让本地版本脱离已交付的提交包。
→ 反驳更强：入口碎片化意味着**本地迭代与交付版本的漂移每天都在扩大**——评审者永远看不到研究库、Sidekick 和本轮全部修复，这比"改了已交付版本"危险得多。但**提交状态只有用户知道**，此决定必须由用户拍板（涉及提交口径，不是纯技术问题）。

**反"本地持久化研究历史"**：localStorage 换设备/清缓存即失，是不是伪连续性？
→ 成立一半。处置：诚实标注「仅保存在本机」，与 UNKNOWN 的诚实纪律同构——明确说边界，比假装有云同步体面。工程量小（一个 IndexedDB 封装 + 研究库读列表），收益是叙事闭环：**研究库从"预置目录"变成"你积累的研究"**。

**反"多公司并列对比"**（README 未做事项里明确不做的大点）：
→ 成立。payload 结构、证据绑定、画布布局全链泛化，工作量是"另一个项目"级；且行业级对比已覆盖主要场景。**放远期，不作为下一个动作。**

**反"分阶段流式 init"**：README 明确反对假进度，而真分阶段（Framer 完成即渲染维度骨架）不违背原则——但工程复杂度高（流式协议 + 逐步校验），且等待已有中止/重试兜底。
→ 成立。**缓行**，等真有用户抱怨 15–30 秒不可接受再做。

**反"加功能"本身（对整个审查方向的反向压力）**：产品的差异化恰恰是**克制与诚实**（UNKNOWN 显式呈现、不给评分、不预测涨跌）。加任何功能都有稀释这个气质的风险。
→ 接受。所以下面的清单里，前两项都是**收敛与衔接**，不是扩张。

## 第五重 · 全貌收束

把四重压力筛过之后的结论，按优先级：

### P0（结构性，先做）
1. **入口收敛**：`/`（首页）定为正式入口，研究库成为标准动线；README / SUBMISSION / 部署 / Run Locally 全部改指向；`/observatory-v5` 保留为兼容路由。⚠️ 涉及提交口径，**需要用户确认交付状态后执行**。
2. **搜索空结果提示**：空列表时明确说「未找到——检索范围仅 A 股（沪深北三所），港股/美股不在索引内」（文案现成，README 里已写了这句）。小改动，直接消掉一个 60 秒信任缺口。

### P1（研究连续性，下一个真正的"功能"）
3. **本地研究历史**：IndexedDB 存研究空间列表 → 研究库「最近研究」跨会话生效，标注「仅保存在本机」。
4. **证据快刷**：数据层只需 0.17–0.6 秒——对 stale 的行情类证据提供「仅刷新数据，不重跑模型」的快路径，配新鲜度标记。这是把"诚实呈现数据年龄"升级为"诚实且可行动"。

### P1.5（文档卫生，随手做）
5. README 测试数字 409/30 → 417/32；Validation 摘要补 RouteWipe/中止重试两条。

### P2（大点，远期，本期不做）
6. 多公司并列对比（证据对齐表）——最有价值也最贵，等入口收敛后再评估。
7. 研究笔记导出（把画布导出为"结论 + 证据 + 来源"的 PDF 报告）——与 evidence-first 同构，成本低于 6。
8. 分阶段流式 init——真进度不违背产品原则，但缓行。

### 明确不做（维持 README 未做事项）
i18n（EN 已按决策关闭，`COPY.en` 留作底稿）、K 线/图表库、语音、组合推荐、账号系统。

---

## 最终判断

**StockLens 的下一个大动作不是加东西，是把已经做出来的东西接到用户面前**：入口收敛（让评审看到同一个产品）+ 研究连续性（让研究库从目录变成资产）。核心闭环、诚实纪律、动效语言这三样已经齐了，而且少见地好——所有后续迭代都应保护这三样，而不是覆盖它们。

唯一需要用户拍板的前置条件：**交付冻结状态**。P0-1 的执行时点完全取决于此。
