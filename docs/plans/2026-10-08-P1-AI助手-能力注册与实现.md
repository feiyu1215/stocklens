## 一、Task 1 核验结论（仓库事实，修正评审假设）

1. **"⌘K Commands" 在本仓库不存在**。画布 `ResearchCanvas.tsx:711` 的 ⌘K/Ctrl+K 绑定的是 AI Lens 开关（`setLensOpen`），不是命令面板。落定：首页/研究库路由由 AssistantPanel 自绑 ⌘K/Ctrl+K，与画布路由互不冲突；画布不做任何改动。
2. **合规是双道确定性规则**（`src/lib/validation/compliance.ts`）：`detectRestrictedInvestmentRequest`（请求预检）+ `findForbiddenOutputPhrases`（输出禁语）。新两条通路两道都接，不构成旁路。
3. **实体解析用服务端真实标的检索**：`src/lib/data/stock-search.ts` 的 `searchStocks`（server-only，扶摇数据源，只返回 A 股）。模型只允许输出公司**名称**，代码一律由检索解析确定——模型编造代码在结构上不可能进入执行层。
4. **限流模式**：`rateLimitResponse(request, {scope, limit})`；新路由 scope：`assistant-intent`（30）、`assistant-explain`（20）。
5. P0 对比路由参数格式：`/research/compare?stocks=<A>,<B>`；payload 可用性检查复用 `loadResearch` + `classifyResearchLoad`（P0 交付）。

## 三、调度链路（已实现）

```
用户输入 → 合规预检（服务端，拦截即 redirect）
        → 确定性规则（lib/v5/assistant/rules，不调模型）：
            导航命令 / 对比+实体提取 / 打开公司研究 / 概念解释 / 泛研究引导
        → 规则未命中：产品功能清单关键词匹配（怎么/如何/在哪类问句）
        → 仍未命中：LLM 分类（/api/assistant/intent，温度0、小token、严格 JSON schema，
           输出非法/超时/未配置 → 结构化降级，绝不猜）
        → 实体解析（searchStocks）：唯一 → ready；多条 → 澄清卡片；无 → 如实说明
        → 能力检查通过的动作以"操作卡片"呈现，用户点击后由页面侧 ActionExecutor 执行
        → concept_explain 由面板继续调 /api/assistant/explain（独立通路，无 stockCode，
           输出经禁语检查，NOT_A_CONCEPT 机制拒绝非概念问题）
```

关键落定点：`src/lib/v5/assistant/{capabilities,rules}.ts`、`src/app/api/assistant/{intent,explain}/route.ts`、`src/components/v5/AssistantPanel.tsx`、ResearchHome 接入（`executeAssistantAction` + ⌘K 绑定 + 顶栏入口）。LLMTask 枚举扩展 `assistant_intent` / `assistant_explain`。

## 四、本轮范围边界

- 接入页面：**首页 + 研究库 + 对比页**（三面共用同一常驻输入条）；**研究空间入口 = 既有 Sidekick（未动，右侧）**。
- 形态（产品拍板，覆盖评审方案"不做常驻悬浮球"的原结论）：
  底部中央是**常驻对话输入条本体**（不是按钮组、不是右下角卡片）；聚焦/发送/⌘K 时从输入条**向上弹出**对话框，
  输入框本身留在原位充作对话框的底部；收起后输入条仍在。研究空间不改（右侧 Sidekick）。
- 移动端：390×844 实测三面输入条均不横向溢出、面板在视口内且底部衔接输入条；
  移动端首次进入会被重定向到研究空间（既有产品决策），故首次访问不经过首页输入条。
- 面板只保留当前一轮交互（单输入+简短反馈+操作卡片），无聊天历史、无持久化。
- compare 澄清时的候选公司卡片点击行为 = 打开该公司研究空间（两步对比组装延后），在面板文案中如实呈现。
- 全市场筛选 / 投资建议 / 双公司 AI 结论 / 研究库跨公司筛选：不做（合规或阶段边界）。

## 五、降级与回滚（按方案 §9.2 落实）

- 意图模型不可用/超时/未配 key → 结构化降级文案，规则层导航与全部既有功能不受影响（单测覆盖"模型挂了也能走规则"的分层：规则匹配在客户端/服务端本地完成，模型只在最后兜底）。
- 解释服务失败 → 面板琥珀色失败态，可重试。
- 回滚 = 隐藏底部常驻输入条 `data-assistant-toggle` 一处（单点开关），无需回滚代码。

## 六、生产实测发现的覆盖缺口与补强（P1 收尾）

**发现方式**：P1 上生产后拿真实问法打 `/api/assistant/intent`，而不是只跑单测。

| 输入 | 修复前（生产实测） | 问题 |
|---|---|---|
| 推荐明天涨幅最大的股票 | `unsupported` + 通用能力边界文案 | 没走合规拦截，靠模型兜底判成"不支持" |
| 买什么股票好 / 帮我选股 | 同上 | 同上 |

这意味着：**合规这条确定性防线只在老通路上成立**，助手这个新入口上，投资建议类请求是"被判不支持"而不是"被守卫拦下"——两者都能挡住输出，但性质不同：前者依赖模型判断，模型换一个就有可能放行。评审 §6.2 的要求是"合规预检是确定性防线"，靠兜底不算数。

**修复**：`src/lib/validation/compliance.ts` 的 `RESTRICTED_PATTERNS` 补 24 个词（涨幅最大/涨幅最高/涨最多/买什么/买哪只/选哪只/帮我选股/推荐买/推荐几只/推荐股票/推荐个股/最值得买/值得投/投资哪只/明天涨/预测涨/翻倍股/牛股/黑马股/潜力股推荐 …），命中后走 `COMPLIANCE_REDIRECT_MESSAGE` + `compliance.suggestedQuestions`，与 followup / diagnosis 同一守卫。

**不误伤的验证**（同批补 5 条用例）：`哪些股票值得关注`、`帮我筛选出符合条件的公司` 不判投资建议（走能力边界说明）；`对比美的集团和格力电器`、`打开研究库`、`ROE 是什么意思` 完全不受影响。
