# AI Research Workspace v1 — 设计决策与验收

日期：2026-10-06  
实验入口：`/lab/ai-workspace-v1`

## 要解决的问题

现有画布有清晰的空间感和自己的交互语言，但 AI 仍像一个附加输入框：上下文不够可见，回答缺少稳定的信息结构，引用与原始证据之间的跳转成本偏高；“新增研究角度”也缺少足够醒目的创建过程和确认节点。

本实验保留缩放、拖拽、焦点光圈、Reading、证据钉住、便签、公司切换、研究架、命令面板和原 AI Lens。新增的是一层可并行工作的 AI Research Sidekick，不以删除旧交互换取表面简洁。

## 参考产品与可复刻部分

| 参考 | 采用的模式 | 不直接复刻的部分 |
| --- | --- | --- |
| [Miro AI](https://miro.com/ai/) | 画布选中对象成为 AI 上下文；右侧 Sidekick；AI 产物先预览再应用 | 不复制通用白板工具栏和大量生成入口 |
| [NotebookLM](https://notebooklm.google/) | 回答绑定来源；点击引用回到原材料 | 不把产品改造成文档资料库 |
| [Perplexity](https://www.perplexity.ai/) | 结论后紧跟引用；建议下一步问题 | 不采用搜索结果流作为主界面 |
| [Claude Artifacts](https://www.anthropic.com/news/artifacts) | 对话与工作对象并排，修改对象保持可见 | 不把研究画布降级为单一文档预览 |
| [ChatGPT Canvas](https://openai.com/index/introducing-canvas/) | 对话与可编辑成果并行，用户显式决定应用 | 不复制通用写作编辑器 |
| [Hebbia](https://www.hebbia.ai/product) | 将复杂问题拆成可验证任务，强调证据链 | 不复制高密度矩阵；当前个人股票研究场景不需要其信息规模 |

判断标准不是视觉相似，而是该模式是否同时满足：保住画布特色、减少任务切换、让 AI 的依据可查、让写入操作可撤回或至少先确认、在 390px 移动端仍能完成阅读与追问。

## 最终交互模型

### 1. 画布就是上下文选择器

用户点选维度、结论或证据后，Sidekick 顶部出现对应上下文标签。发送问题时沿用现有 `/api/followup` 和真实 evidence IDs，不另造一套 AI 数据通道。

### 2. 回答是研究结果，不是聊天气泡堆叠

用户问题保留对话气泡，AI 回答按研究语义展示：

- 摘要
- 可以确认
- 基于证据的推断
- 仍不能确认
- 引用的证据

引用可以直接打开对应 Reading 维度并钉住原始证据。回答可以保存为画布便签，形成“问 → 查 → 留在画布”的闭环。

### 3. 新增角度先生成研究计划

输入模糊意图后先看到标题、研究问题、验证清单、预计证据量和“尚未写入画布”状态。只有点击“加入研究空间”才调用 `/api/research/dimension`。这让创建动作醒目，同时保留旧的建议节点和原添加能力。

### 4. 桌面并排，移动端接管

- 桌面：画布与 360–560px 可调 Sidekick 并排。
- Reading + Sidekick：Reading 使用左侧完整可用宽度，避免画布缩略、论点、证据、AI 四栏挤压。
- 移动端：Sidekick 全屏；关闭后恢复 Reading/画布；底部 AI Lens 保持可见并可重新进入。

### 5. 正式研究使用同一套编号

首次生成和后续确认加入的研究维度不再分区。所有正式研究共用同一套视觉与编号：已有维度先按研究优先级排列，后续维度保持写入顺序，直接获得下一个编号。

默认布局使用“有序骨架 + 编辑错落”：编号仍按三列从左到右、从上到下阅读，但每行采用一组有边界的高低差与左右偏移。固定安全间距阻止长标题互相粘连，节奏偏移避免九宫格式的呆板；新增维度只取下一个节奏位，不会落到画布中心。用户仍然可以拖动单个标签形成手动位置，工具栏可随时“恢复自动”。

尚未成为正式研究的 AI 建议放在公司名称下方竖向排列，沿用正文标签的编号、标题和状态排版，不使用白色卡片容器。单击直接加入并自动编号，拖动则可以指定加入位置。

证据不足只通过标题下方的琥珀色状态点表达，正式标题仍保持正文黑色。后续加入的研究在 hover 或焦点菜单中提供“移除”；移除后其余编号和自动位置立即回流，并提供 7 秒撤销入口。

刷新时仍恢复便签、选择、手动位置和阅读上下文；当 Sidekick 改变可用宽度时，会按当前分栏重新计算相机视角，避免旧视口把标签恢复到屏幕外。

## 已验证路径

| 路径 | 结果 |
| --- | --- |
| 点选“增长韧性” | Sidekick 出现维度上下文；原画布仍可操作 |
| 输入“海外收入增长是否真正带来利润贡献？” | 生成研究计划草稿，确认后真实写入第 8 个维度 |
| 追问“为什么利润增速弱于收入？” | 返回真实结构化回答，区分事实、推断和未知 |
| 点击“营业收入单季同比”引用 | 打开“增长韧性”Reading 并钉住对应 VERIFIED 证据 |
| 保存回答 | 画布生成 AI 研究便签 |
| 刷新实验页 | 研究状态恢复，当前分栏下所有标签仍在可视区 |
| 新增角度后重新排列 | 新标签获得下一个编号并进入下一个自动位置 |
| 点击左侧“待加入”建议 | 直接加入正式研究；也可以拖动到指定位置 |
| 移除后续加入的研究 | 标签消失，编号与自动位置回流；可在提示条中撤销 |
| 点击“恢复自动” | 清除手动坐标，按编号稳定重排 |
| 390 × 844 | 无页面横向溢出；Sidekick 可关闭和重新打开 |

## 推进建议

这个方向已具备进入产品代码的依据，但当前仍放在 Lab 路由，便于比较原版。下一轮应先做 5–8 位目标用户的任务测试，重点记录三项：从画布发起追问的发现率、引用回看率、研究计划草稿的确认/放弃比例。达到稳定数据后，再将 Sidekick 设为正式入口；旧 AI Lens 保留为快速启动器。

## 2026-10-07：研究入口与历史行情

首页 / 与 /research 展示公司搜索和研究矩阵。所有已进入的公司自动加入持久研究库，旧收藏与最近访问合并迁移；记录保存在当前浏览器，尚未提供跨设备同步。研究库回跳使用 resume=1，恢复已保存的研究载荷与画布现场；刷新研究仍由用户明确发起。普通新增标签立即清除手动偏移并进入连续编号布局，拖放新增保留用户指定位置。

研究空间响应新增 marketHistory，直接传递已归一化的扶摇前复权日线。趋势图支持 20/60/120 交易日和全部记录；少于两个有效点不绘图。美的录制示例补入实际 API 返回的 195 个点，截止 2026-09-30。

验证：TypeScript、全 src ESLint、417 个测试和生产构建通过；浏览器验证公司搜索、新增后自动布局、研究库往返恢复与移动端页面。
