## 一、这是什么项目

**个股证据诊断工具**：把一家 A 股公司的当前状态组织成可探索的研究画布。AI 生成研究维度，确定性代码负责全部金融数字，每条结论可回溯到原始证据，无证据返回 UNKNOWN。不评分、不预测涨跌、不给买卖建议。

**一句话产品原则**：Evidence first. Conclusions second. 所有迭代都不得破坏这条（详见 `README.md` 的 Product Choices）。

## 五、我认为值得做、但还没做的事

按优先级。完整推理与反方压力见 `docs/design-audit/2026-10-08-product-review.md`，这里只留结论。

### P0（结构性）

1. **入口收敛**。线上所有地址指向 `/observatory-v5`，而首页 `/`、研究库 `/research`、Sidekick、本轮全部修复都只在本地——**外部用户与评审看到的和本地不是同一个产品**，且漂移每天在扩大。做法：`/` 定为正式入口，README / SUBMISSION / 两处部署全部改指向，`/observatory-v5` 保留为兼容路由。**执行时点取决于拍板事项 1。**
2. **搜索空结果提示**。搜港股/美股返回空列表且无任何反馈（`已知边界.md` 自认）。改法现成：空列表时明确提示「检索范围仅 A 股（沪深北三所）」。小改动，消掉一个 60 秒信任缺口。

### P1（研究连续性——下一个真正的"功能"）

3. **本地研究历史**：IndexedDB 存研究空间列表，研究库「最近研究」跨会话生效。不需要账号系统；诚实标注「仅保存在本机」。
4. **证据快刷**：数据层实测只占 0.17–0.6 秒（慢的是两次模型调用）。对 stale 的行情类证据提供「仅刷新数据，不重跑模型」的快路径——把"诚实呈现数据年龄"升级为"诚实且可行动"。

### P1.5（文档卫生，随手）

5. README Validation 写的是 409/30，实际已是 **417/32**；Validation 摘要可补 RouteWipe 与中止/重试两条。

### P2（大点，远期，需立项再动）

6. 多公司并列对比（证据对齐表）——最有价值也最贵，payload/证据绑定/布局全链泛化。
7. 研究笔记导出 PDF（结论+证据+来源的文档化）——与 evidence-first 同构，成本低于 6。
8. 分阶段流式 init（真进度，非假进度）——已有中止/重试兜底，缓行。

1. **交付冻结状态**。产品是否已提交？提交包还能不能更新？→ 直接决定 P0-1 入口收敛现在做还是提交后做，也决定 §三那批未提交改动的去向。**这是唯一卡住 P0 的前置条件。**
2. **未提交改动的提交计划**。四轮工作（含另一位 AI 的画布布局与其配套测试）目前全部悬在工作区。需要确认：谁来做 commit、按什么粒度拆、commit message 口径。
3. **生产构建验证**。`next build` 与 `next dev` 共用 `.next`，**不能并发**（试过一次，17 分钟卡死后终止，dev 无恙）。当前 dev server 常驻（端口 3000）。需要：授权停 dev → 单独跑 `next build` → 按 `docs/PROJECT_GUIDE.md` 流程部署。约几分钟。
4. **P2 大点立项与否**。6/7/8 做哪个、什么时候做、做到什么深度——这是产品方向决策，不是工程决策，等拍板后再排期。

## 七、工程纪律（多 AI 协作踩过的坑，接手必读）

- **构建与 dev 互斥**：跑 `next build` 前必须停掉 `next dev`，否则争用 `.next` 卡死。
- **交互结论只认真实指针**：改交互必须用 Playwright + 真实 Chromium 实测（点击、`elementFromPoint`、相位属性），不做推理替代。rect 审计算不到 `after:` 伪元素热区。
- **数字必须有真实溯源**：所有实测数字（像素、秒数、测试数）来自工具量测，不许编。README/文档里的数字要与代码同步更新（409/32 的漂移就是这么来的）。
- **诚实呈现边界**：UNKNOWN 就写 UNKNOWN，失败态就写失败；0 实际接入的东西不得呈现为 live。这条是产品底线，回归时优先检查。
- **AI 写代码的回归风险**：本项目由多个 AI 先后修改，曾发生"另一个 AI 把自由排版改成刚性网格并把测试固化"的回归。改布局前先 `git diff HEAD` 看未提交改动，改动后跑全量 `vitest`（含 `tests/v5-canvas-layout.test.ts` 的 3 断言）。
- **测试注入**：`?testFailure=research-init`（dev-only）可强制 init 失败，用于验证失败态/重试，不要带进生产叙述。
